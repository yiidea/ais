# ADR-0002：模型作为查询规划器

- **状态**：已接受
- **日期**：2026-10-30

## 背景

传统 CBO（基于代价的优化器）依赖对 SQL 的精确理解与统计信息。AI 负载的查询意图是自然语言 + 约束，无法直接用 SQL 表达，也不适合用规则穷举。

## 决策

定义一个 **Planner 接口**，允许模型（本地小模型 / 远程大模型）、规则引擎、缓存 ANY 实现。规划器输出 **有界的执行计划 DSL**，经 Verifier 校验后执行。

**关键约束**：
1. 规划器不直接访问数据，只接收数据摘要（catalog + 统计 + 历史）。
2. 输出 DSL 有算子白名单、资源上限、无副作用检查。
3. 规划失败必须能确定性回退到规则计划。
4. 每次规划的结果与代价模型反馈绑定，用于再训练。

## 后果

**正面**
- 意图表达不再受 SQL 语法限制。
- 规划能力随模型进步自动提升。
- 可针对不同部署（本地/云）选择不同规划器。

**负面**
- 引入 LLM 延迟（v2 目标 < 150 ms；未来本地小模型 < 40 ms）。
- 规划结果不可完全确定，需要 Verifier 与回退机制兜底。
- 规划器可能产生幻觉计划，必须通过算子白名单与沙箱阻止。

**缓解**
- 意图分类器优先走规则/缓存路径，只有复杂意图才调用 LLM。
- 计划缓存 + 历史计划复用。
- Verifier 的失败会作为负样本反馈给代价模型。
