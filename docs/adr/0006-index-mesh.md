# ADR-0006：索引网格而非单一索引

- **状态**：已接受
- **日期**：2026-10-30

## 背景

AI 召回通常需要多路检索（向量 + 关键词 + 标签 + 时间 + 溯源），如果用单一索引（例如只支持向量），应用需要额外集成其他系统；如果让每种检索独立存储，又会产生一致性问题。

## 决策

所有索引共用同一个 Append-Only 真源，**索引网格（Index Mesh）** 并列维护多种索引：

- Vector（HNSW / IVF-PQ）
- Sparse Inverted
- Timeline
- Provenance Graph
- Scalar / Tag
- Semantic Fingerprint（LSH）

每个索引独立构建、独立合并、可随时增删。

## 后果

**正面**
- 单一写入 → 多索引并行更新，一致性由日志保障。
- 可对不同查询选择不同索引组合。
- 支持渐进式索引（仅建必要索引）。

**负面**
- 写入放大：一次写需更新多个索引。
- 存储空间增加。
- 索引构建队列可能互相竞争。

**缓解**
- 通过代价模型 / 访问统计决定哪些索引必须实时构建、哪些可异步。
- 写放大目标 < 2.5×（v3 < 1.5×）。
- 构建队列与前台读走独立 IO 队列。
