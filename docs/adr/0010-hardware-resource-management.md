# ADR-0010：硬件资源管理的参数化方式与后端选择判据

- **状态**：已接受
- **日期**：2026-11-02

## 背景

[02-kernel.md](../chatgpt/02-kernel.md) §3 给出了数据放置的三种策略与代价模型的符号形式 `C(r,o,t) = αL + βT + γP + δM`，[04-kernel-interfaces.md](../chatgpt/04-kernel-interfaces.md) §6 冻结了设备层接口（`StorageDevice` / `MemoryTierManager` / `IoExecutor`，含 I1–I5），[ADR-0004](0004-bypass-kernel-io.md) 定了「io_uring 为主、SPDK 为可选、POSIX 回退」的优先级。

但有四个空白会在实现期立刻造成分歧：

1. **代价模型的四个分量怎么算、权重从哪来。** 直接用原始值加权意味着 `α` 的取值取决于 `L` 的单位——Hardware Profile 哪天从 ns 改成 µs，权重就静默失效，且没有任何报错。
2. **持久性约束怎么进入模型。** 如果写成「很大的惩罚项」，拥塞时惩罚会被压过去，权威副本被放到 DRAM。这是正确性事故。
3. **NUMA 亲和只说了一半。** [04 §6.3](../chatgpt/04-kernel-interfaces.md) I1 说了「每 NUMA 节点一个 reactor 线程」，但没说投给哪个 reactor、缓冲区放哪个节点。缓冲区放错节点，DMA 每次跨节点；reactor 投错节点，ring 与完成队列跨节点。
4. **后端判据缺失，且运行期能不能换没说。** [ADR-0004](0004-bypass-kernel-io.md) 给了优先级但没给判据；更关键的是没有回答「io_uring 在运行期失效时怎么办」——这个问题的答案决定了整套耐久语义能不能被证明。

[04 §1.3](../chatgpt/04-kernel-interfaces.md) 明确「批量大小、队列深度、阈值」「NUMA 亲和如何设置」属于**不冻结**的内容，因此本文不冻结数值，只冻结**推导方式与硬边界**。详细的推导、公式与验收用例见 [07-hardware-resource-management.md](../chatgpt/07-hardware-resource-management.md)，对应的可测试不变量编号是那里的 `HRM1`–`HRM8`（[07 §6](../chatgpt/07-hardware-resource-management.md)）。

## 决策

1. **代价模型的四个分量有明确来源，且分量之间不重叠。**
   - `L` = 设备固有访问延迟 × 尺寸放大因子，**不含排队延迟**（排队归 `P`；两处都算会在拥塞时重复惩罚，让模型退化到加剧拥塞）。
   - `T` = 传输成本（数据不在目标资源时的搬运代价）。
   - `P` = 目标资源压力，`util(r)^k`，`k` 为域配置。
   - `M` = 迁移成本（读旧 + 写新 + 元数据）。
   分量定义见 [07 §2.1](../chatgpt/07-hardware-resource-management.md)。

2. **先归一化再加权，权重无量纲（HRM2）。** 每个分量在可行集内做 min-max 归一化到 `[0,1]`，再以 `α+β+γ+δ = 1` 加权。

   理由：未归一化的权重是「量纲的倒数」，单位一变排序就静默改变。归一化后权重表达的是纯粹的偏好比例，与硬件与单位无关。

   跨对象 / 跨时间比较的场景（缓存准入阈值、迁移触发阈值）改用固定基准归一化，不能用组内归一化——两者的用途必须写清。

3. **硬约束先过滤，代价模型只排序（HRM1）。** 容量、持久性（`Authoritative` 副本只能在持久介质；断言见 [03 §10](../chatgpt/03-consistency-kernel.md) INV5）、角色（`Cache` / `WorkingSet` / `Replica`）、故障域、格式与对齐、设备健康、耐久要求（放置所需等级 ≤ `max_durability(r)`）、域配额，这八条在排序**之前**作为过滤器生效。

   理由：**代价模型永远不应该有能力越过硬约束**。硬约束表达的是正确性与隔离性，不是可以与性能调和的取舍。若写成惩罚项，拥塞时惩罚被压过去 → 权威副本落在 DRAM → 掉电丢数据。

   其中**故障域**一条是本文新增的：[02-kernel §3.9](../chatgpt/02-kernel.md) 讨论了「单块 NVMe 物理损坏后无法恢复数据」的风险，却从未给这个概念命名。该条依赖本文引入的 `FaultDomainId`，在该类型定义并接入 `ResourceStats` 之前**无法执行**。

4. **放置决策是确定性的（HRM3）。** 输入是显式快照（Hardware Profile + `ResourceStats` + 对象属性 + 域配置）；禁止读时钟、禁止随机源、禁止读可变全局状态；平局按 `ResourceId` 升序打破。

   理由：[04 §2.6](../chatgpt/04-kernel-interfaces.md) C5 已禁止内核直接读时钟，本决策把同一要求延伸到放置路径。放置结果若掺入时间或随机性，则不可复现、不可调试、不可对拍。

5. **放置结果写进 WAL 的映射记录，恢复期从不重新推导（HRM4）。**

   WAL 里存的是 `device_id` + `device_offset` + `length`（[03 §2.3](../chatgpt/03-consistency-kernel.md) 的 `ExtentAllocBody`），**不是** `PhysicalLocation` 枚举——后者带 `namespace_id` / `lba`，是**解析之后**的物理位置视图，解析规则归设备层。

   推论：代价模型的任何参数都可以自由、随时重新标定，且只影响新写入；已落盘数据的物理位置由 WAL 决定。

   理由三点：参数漂移（改一次权重就让历史数据的物理位置全变，旧 extent 变孤儿）、非确定性（重启时 `util(r)` 已变）、迁移语义冲突（绕过 [03 §7](../chatgpt/03-consistency-kernel.md) 的协议多出一条移动路径）。

   这条决策把「调参」变成安全操作：改配置不需要停机窗口，也不需要数据迁移。

6. **NUMA 亲和定三条缓冲规则与一条投递规则（HRM5、HRM6）。**
   - **总原则：用放置消除跨节点，而不是优化跨节点。** 数据常驻在消费它的 worker 所在节点（home node 固定）就没有 DMA、没有跨节点。
   - N1 读且**内存命中**：缓冲放在**内存域所在节点**（home node）。
   - N2 读且**设备取数**：缓冲放在**设备所在节点**（DMA 目标缓冲必须在设备近端）；大批量顺序消费时把消费线程临时绑到设备节点，第一版至少做到「消费方跨节点读一次」并记为已知次优路径。
   - N3 写：缓冲放在**发起方（内核线程）所在节点**——把它挪到设备节点等于把 CPU 的写变成跨节点写，而写路径单次传输量小。
   - 设备操作投递给**设备所在** NUMA 节点的 reactor（与 [04 §6.3 I1.1](../chatgpt/04-kernel-interfaces.md) 一致：I1 原文的「该 NUMA 节点」由 I1.1 消歧义为**设备所在的**节点）。home node 与 reactor 路由作用对象不同（数据的位置 vs 执行者的位置），不冲突。
   - 跨节点惩罚因子**必须实测**，不得写成常量；无 NUMA 拓扑信息时退化为单节点模型，不假装有亲和。

7. **队列深度的硬边界与调整规则（HRM7）。**
   - 域预算拆成两份：`qd_budget = qd_usable + qd_flush_reserve`；生效 QD = min(设备上报上限, 域预算)。**普通 I/O 的在途上限是 `qd_usable`，不含 flush 的预留槽位。**
   - 初始 QD = min(生效值, 32)；**batch 初值按路径给**：读 16、写 4、后台 32、flush 1（区间见 [07 §4.7](../chatgpt/07-hardware-resource-management.md)）——不存在一个全局 batch 初值。
   - 自适应只看可观测指标（inflight / lat_p99 / util / 滚动基线），阈值用 `qd_usable` 而不是生效 QD；**延迟超标且设备利用率 < 60% 时不调整**（瓶颈不在设备，先归因）。
   - 降 QD 快、升 QD 慢；升需连续满足 3 个窗口；每次调整记录指标。
   - QD 预算中**必须为 flush 预留至少一个槽位**，且 flush 走独立优先级队列不被饿死；预留是从设备额度里划出来的，不是额外加的。
   - 队列满且超过 deadline 时返回 `Retryable(Backpressure)`，**不静默截断、不静默缩小 batch、不自动重试**（[04 §2.3](../chatgpt/04-kernel-interfaces.md) C1）。

8. **后端选择是启动期决策；运行期只允许能力降级，不允许切换后端（HRM8）。**

   - 启动期按三条判据依次求值：**能力**（探测）→ **部署形态**（允许吗）→ **性能画像**（值得吗）。共享部署一律禁用 SPDK；SPDK 仅在 io_uring 路径实测不达 SLO 且压测收益达门槛时启用。
   - O_DIRECT 是**每个文件**的独立选择（日志 / 索引段 / 大 payload 开，小文件与元数据关），与后端正交；未对齐的调用必须返回错误，**不得静默降级为 buffered**；引擎所有文件 I/O 走统一文件层，不允许业务代码直接 `open`。
   - **三个后端对 `DurabilityLevel` 三档的可观测行为必须完全一致**（`Durable` → 保留、`Write` → 丢失、`None` → 丢失），由掉电对拍验证。POSIX 路径的 `Durable` 用 `fsync` 达到（O_DIRECT 只让数据绕过 page cache，元数据仍需 fsync）。
   - 运行期允许：设备故障 / 降级可见并退出候选集、ring 损坏视为设备故障。运行期禁止：后端热切换、O_DIRECT 与 buffered 互切、有并发写入时更换 `StorageDevice` 实现。

   禁止热切换的三条理由：SPDK 与内核驱动对设备的所有权互斥，切换要重置控制器状态；切换点两侧哪些写已持久无法证明，「已提交 = 已持久」的契约被破坏；切换期间的错误在 [04 §2.3](../chatgpt/04-kernel-interfaces.md) 的四分类里没有位置。

   **不允许任何路径把 `Durable` 悄悄降级为 `Write`**——那会让 SLO 测试通过但数据在掉电时丢失。

9. **不新增冻结项。** 本 ADR 记录的是推导方式与硬边界，不是数值。[04 §1.3](../chatgpt/04-kernel-interfaces.md) 已把「批量大小、队列深度、阈值」「NUMA 亲和如何设置」列为明确不冻结的内容，因此本文不向 [04 §1.2](../chatgpt/04-kernel-interfaces.md) 的冻结清单（F1–F15）添加条目。[04 §6.3](../chatgpt/04-kernel-interfaces.md) 的 I1.1 是一条**消歧义**，不是冻结清单条目。

   本文所有规则都落在 `MemoryTierManager::allocate` 的入参 `MemoryAllocationRequest`（已有 `numa_node` / `device_id` / `alignment` / `access_pattern` 字段）与 `IoExecutor`（已有 `submit_batch_and_wait`）的**实现内部**，不改变任何 trait 签名。

   一项待办：四个类型被引用但从未定义、或刚刚引入——`AccessPattern`（[02-kernel.md](../chatgpt/02-kernel.md)）、`ResourceStats`（[04 §6.2](../chatgpt/04-kernel-interfaces.md)）、`DeviceHealth`（[04 §6.1](../chatgpt/04-kernel-interfaces.md) 的 `health()` 返回类型，被 [05 §3.5](../chatgpt/05-kernel-test-harness.md) 当作已冻结类型引用）、`FaultDomainId`（[07 §2.3](../chatgpt/07-hardware-resource-management.md) 新引入）。[07 §2.3](../chatgpt/07-hardware-resource-management.md) 给了建议定义，但它们进入冻结清单需要单独一条 ADR。

## 备选方案

1. **直接用未归一化的原始值加权** → 权重是「量纲的倒数」，Hardware Profile 的单位一变（ns → µs），排序静默改变且无报错。改用归一化。
2. **把持久性约束写成大惩罚项** → 拥塞时惩罚被压过去，权威副本落到 DRAM，掉电丢数据。改用硬约束前置过滤。
3. **恢复期用当前代价模型重新推导放置** → 参数一改历史数据的物理位置全变；重启时资源占用已变导致结果不可复现；绕过迁移协议多出一条移动路径。改为一律读 WAL。
4. **用「时间衰减」等隐式信号参与放置决策** → 结果不可复现、不可对拍，且让「所有影响放置的因素都显式可观测」这条原则失效。改为一律用显式快照。
5. **把 `c_point` 定义成「读完整个对象」** → 点查与扫描在代数上几乎相同，代价模型无法解释索引为何优于全扫，[06 §3.2](../chatgpt/06-index-recovery.md) 的 A / B 策略退化成候选数之比。改为：点查只取回一个逻辑 extent，扫描读完全部 extent。
6. **在迁移成本 `M` 里加一个方向项，让降级显式更贵** → `M` 量的是搬运量，方向性代价来自「写阻塞提交」；把它折成一个乘子等于引入一个没有实测依据的系数，与本 ADR「不写常量、一律实测」的原则冲突。改为：`M` 保持对称，降级与否由策略与迁移协议决定。
7. **缓冲区一律分配在发起方节点** → 设备取数时每次 DMA 都跨节点。改为分层：内存命中放 home node，设备取数放设备节点。
8. **缓冲区一律分配在设备节点** → 写路径的 CPU 写变成跨节点写，而内存命中的读也不必经过设备。改为分层：读按命中与否分流，写留在发起方节点。
9. **投递给调用方所在节点的 reactor** → ring 与完成队列跨节点，且设备 DMA 仍跨节点，等于两处都没优化。改为投递到设备所在节点。
10. **把 home node 固定与 reactor 路由混成一条规则** → 两者作用对象不同（数据常驻在哪个内存域 vs 设备操作由哪个节点的线程执行）。混成一条会在「热点数据在 node 1、设备在 node 0」时给出互相矛盾的要求。改为两条独立规则，并明确各自的作用对象。
11. **把跨节点惩罚写成常量（如「远端 = 1.5×」）** → 不同 CPU、NUMA 拓扑、互联方式差异很大，常量在另一台机器上就是错的，且会制造假的 benchmark 收益。改为一律实测。
12. **QD 一开始就设到设备上限** → 尾延迟随队列深度上升，SSD 内部并行度用尽后只增加排队。改为保守起步 + 实测调节。
13. **延迟超标就一律调 QD** → 设备利用率只有 50% 时说明瓶颈在 CPU 或锁，加深队列只会更糟。改为先归因，util < 60% 时不动。
14. **flush 与普通读写共用队列且不预留槽位** → QD 打满时 flush 排在队尾，事务提交延迟变成「队列排空时间」，且 QD 越深提交越慢，形成负反馈。改为预留槽位 + 独立优先级队列。
15. **普通读写可以占用 flush 的预留槽位** → 预留形同虚设，flush 被普通 I/O 饿死。改为：普通 I/O 的在途上限是域预算里的普通份额，不含预留槽位。
16. **队列满时静默截断或缩小 batch** → 调用方以为整批都完成了。改为返回 `Retryable(Backpressure)`。
17. **运行期在 io_uring 与 SPDK 之间热切换** → 设备所有权互斥、切换点的持久性边界无法证明、错误无处分类。改为启动期决策 + 运行期只降级；io_uring 彻底失效时上抛 `Io { op }` 由上层决定重启。
18. **POSIX 回退路径把 `Durable` 降级成 `Write`** → 回退只降性能不降语义这条承诺被打破，且掉电丢数据。改为 POSIX 用 `fsync` 达到同等的 `Durable`，代价是延迟更高。
19. **未对齐时静默降级为 buffered** → 误以为走了直写路径，性能与写放大都不可预期。改为返回错误。
20. **用惩罚项表达「DRAM 不能当权威副本」** → 这不是「代价高」，而是「不合法」。改由硬约束表达。

## 后果

**正面**

- 代价模型的权重变成了真正的偏好比例，换硬件、换单位不需要重标定。
- 持久性 / 容量 / 故障域这些正确性约束不可能被性能压力压过去。
- 代价模型可以随时重新标定且不影响已落盘数据——运维改配置是安全操作，不需要停机窗口，不需要数据迁移。
- 放置决策可复现、可对拍、可在假设备上完整验证（[05-kernel-test-harness.md](../chatgpt/05-kernel-test-harness.md)）。
- NUMA 规则把「缓冲区放哪」「投给谁」从实现者个人偏好变成可断言的契约。
- 后端选择的判据是可解释的：排障时能说出「这台机器现在跑的是哪条路径、为什么」。
- 三后端耐久语义一致有了可执行的验证方式（掉电对拍），「回退只降性能不降语义」不再只是一句承诺。

**负面**

- 归一化增加了每次放置决策的计算量（需要在可行集上取极值）；单次决策成本必须实测（B1，目标 P99 < 50 µs）。
- 放置结果写进 WAL 增加了映射记录的字段（home node），并让 WAL 格式多一个需要版本管理的维度。
- 「运行期不切换后端」意味着 io_uring 彻底失效时只能重启引擎，牺牲了可用性换取语义可证性。
- flush 槽位预留会占用一部分 QD 预算，牺牲一点峰值吞吐换取提交延迟的稳定。
- 第一版在 N2（设备取数）场景下只能做到「缓冲在设备节点 + 消费方跨节点读一次」——没有实现「把消费线程临时绑到设备节点」，因此热点对象在设备节点与 worker 节点不同时仍有一次跨节点读。
- `AccessPattern` / `ResourceStats` / `DeviceHealth` 尚无冻结定义，实现前必须补一条 ADR，否则不同实现者会各自定义不同的类型。`FaultDomainId` 同理，且故障域硬约束在它定义前无法执行。

**缓解**

- 归一化的计算量在可行集很小时可忽略；可行集大时用增量统计（复用上一次的极值）近似，误差只在跨决策比较时出现，而跨决策比较本来就用固定基准归一化。
- home node 可以作为映射记录的一个可选字段引入，老版本读取时忽略；WAL 记录体的版本兼容走 [03 §2.2](../chatgpt/03-consistency-kernel.md) 的帧格式机制（帧头的 `reserved` 字段与 `flags` 位是载体），[04 §14.3](../chatgpt/04-kernel-interfaces.md) 的接口变更流程只在同时改 trait 签名时才适用。
- 「重启而非热切换」把问题变成可观测的启动期失败（启动自检会探出 io_uring 不可用），而不是运行期的神秘崩溃。

- `AccessPattern` / `ResourceStats` / `DeviceHealth` / `FaultDomainId` 的 ADR 已在 [07 §9](../chatgpt/07-hardware-resource-management.md) 与本文决策 9 中列为显式待办，作为实现硬件路径的前置条件。
