# ADR-0005：三级一致性模型（Causal / Strong / Eventual）

- **状态**：已接受
- **日期**：2026-10-30

## 背景

AI 负载对一致性的需求各不相同：

- Agent 记忆：只需要自己写入的可见性 + 跨 Agent 最终一致。
- 策略 / 凭证：必须线性一致。
- 多模态大对象：最终一致即可。

如果只用一种一致性（例如强一致），会造成大量分布式协调成本，影响延迟。

## 决策

提供服务端可配置的 **三级一致性模型**：

| 模式 | 保证 | 协调成本 |
|---|---|---|
| Causal（默认） | 单个 writer 因果序；跨 writer 最终收敛 | 低（半同步 + 因果令牌） |
| Strong | 线性一致 | 高（quorum + 租约） |
| Eventual | 最终一致 | 最低（无主写入） |

## 后果

**正面**
- 默认场景低延迟、高并发。
- 强一致只用于真正需要它的域。
- 可随业务演进在同一引擎内升级一致性等级。

**负面**
- 用户需要理解三种模式并选择。
- Causal 模式下的冲突必须被表达（ConflictSet），不能悄悄覆盖。

**缓解**
- 默认 Causal，配置错误时给出清晰提示。
- 提供冲突查询 API，让应用显式处理冲突。
- 与溯源模型结合，所有冲突都可解释。
