# ADR-0003：Append-Only 语义日志作为唯一真理源

- **状态**：已接受
- **日期**：2026-10-30

## 背景

系统需要支持多种索引（向量、稀疏、时间线、图），且这些索引会随需求变化。如果索引和原始数据共同作为真源，维护一致性会非常复杂。

## 决策

所有写入先形成一条 **语义日志记录**，追加到日志。日志是唯一真理源；所有索引都是可从日志重建的派生视图。

## 后果

**正面**
- 写入路径极短：追加 + epoch 分配。
- 崩溃恢复简单：校验日志 + 增量重建索引。
- 索引演进低成本：新增索引只需回放。
- 审计友好：日志本身即完整变更历史。

**负面**
- 空间放大：日志 + 索引双重存储。
- 需要维护「日志水位 → 索引构建水位」，滞后期间查询要处理「未索引对象」。
- 索引合并（compaction）可能消耗大量 IO。

**缓解**
- 日志按段存储 + 段级 GC；冷段压缩后放入对象存储。
- 构建滞后期间查询走「回退扫描路径」。
- 构建队列与前台读分离，并在 NUMA 亲和上独立调度。
