# ADR-0004：绕过内核：io_uring 为主，SPDK 为可选

- **状态**：已接受
- **日期**：2026-10-30

## 背景

现代 NVMe SSD 的延迟已经低于传统 VFS + page cache 带来的开销。如果继续用 `read()/write()` 加 4 KB 页缓存，吞吐和延迟会被内核路径吃掉很大比例。

## 决策

实现一个 **Storage HAL**，优先使用 io_uring（注册缓冲区 + SQPOLL + O_DIRECT），在专用部署上可启用 SPDK（用户态队列）。无 io_uring 的环境自动回退到 `preadv2` / epoll 方案。

## 备选方案

1. **仅用 mmap + page cache**：实现简单，但延迟高、缺页抖动，不符合硬件直通目标。
2. **仅用 AIO**：Linux AIO 对 buffered IO 支持有限，效果不佳。
3. **强制 SPDK**：需要独占设备与 root 权限，部署门槛过高。

## 后果

**正面**
- 4 KB 冷读目标 < 8 µs，硬件性能利用率高。
- 注册缓冲区消除频繁内存映射与拷贝。
- 面向批量 IO 优化 SSD 内部并行度。

**负面**
- 系统调用/内核版本兼容性问题（io_uring 特性差异）。
- 直接 IO 使内核缓存不可用，必须自己管理内存层级。
- SPDK 需要设备独占，运维复杂度高。

**缓解**
- 能力探测 + 回退矩阵（见 04-hardware-path.md §8），保证功能一致，仅性能降级。
- 所有路径共享同一套语义测试。
- 明确 SPDK 为可选，默认不启用。
