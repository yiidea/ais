# 05 — AI 原生特性

本章是AINS 区别于「普通向量库 + 普通数据库」的核心。每一节都对应一类 AI 负载的真实痛点。

## 1. 意图级并发控制（Intent-Level MVCC）

### 1.1 问题

传统 MVCC 提供「全局一致快照」。但对 Agent 而言，真正的需求是：

- 我（Agent A）应该看见自己刚写的记忆。
- 我不一定需要看见 Agent B 刚写的内容（除非我去查询那个域）。
- 两个 Agent 同时写同一主题时，系统要保留双方，并能在召回时排序/去重。

### 1.2 设计

- 每个写入携带 `writer_id`、`causal_token`、`epoch`。
- 读取时构造 **因果快照**：`{ writer_id, seen_epoch_by_writer }`。
- 可见性判定：

```
visible(obj) = obj.epoch <= snapshot.own_epoch[obj.writer]
            || obj.epoch in snapshot.explicitly_visible
```

- 对于「共享事实」域，使用 **收敛集**：写入先进入私有的 pending 集合；通过因果广播后转正。未被广播的高置信写入（例如用户直接给的偏好）可以立即对全局可见。

### 1.3 冲突表示

**不隐藏冲突。** 当检测到同一事实的多个版本：

- 记录为 **冲突组（ConflictSet）**，每个成员带来源、时间、置信。
- 召回时默认返回「最新 + 置信最高」；若意图要求 `min_confidence` 或 `explain_conflict`，返回冲突详情。
- 后台 `consolidate` 意图可生成摘要合并版。

这与传统数据库的「最后写入者获胜」相反：AINS 把冲突当成一等证据。

## 2. 语义幂等

### 2.1 问题

LLM 会重复生成完全相同或近似相同的事实。如果每次都写入，会产生大量语义重复，污染检索结果并消耗存储。

### 2.2 语义指纹

写入时计算 **语义指纹（Semantic Fingerprint）**：

```
fingerprint = LSH(embedding) ⊕ token_set(payload 归一化后)
minhash_sketch = MinHash(k=128) 归一化 token 的 shingles
```

- 用 LSH 找近邻；若近邻的语义相似度 ≥ 阈值（默认 0.95），则不新增对象，而是：
  - 在已有对象的 tags 上追加 `writer_id`、`timestamp`、`evidence`；
  - 更新 `last_seen`；
  - 置信度做贝叶斯更新（多次独立来源 = 高置信）。
- 在近似但不完全等价时（0.85~0.95），标记为候选，由 `consolidate` 阶段处理。

### 2.3 幂等键两种模式

| 模式 | 语义 | 用途 |
|---|---|---|
| `strict` | 完全相同的 payload + provenance → 视为同一写 | 精确重试 |
| `semantic` | 语义近似 → 合并 | Agent 记忆、事实库 |

## 3. 溯源图（Provenance Graph）

### 3.1 模型

溯源是一个 **有向、带标签、带权重** 的图：

```text
Object A (fact: "用户喜欢暗色主题")
   ▲ derived_from (w=0.9)
   │
Object B (user utterance, 2026-10-30)
   ▲ cited_by
   │
Object C (Agent run #1234, model=gpt-x)
```

节点：语义对象、外部文档、用户输入、模型运行。
边：`derived_from` / `cited_by` / `summarized_from` / `contradicts` / `supersedes`。

### 3.2 溯源查询

- `provenance(id, depth, direction)`：返回子图。
- **可信度传导**：从源节点沿边传导置信度（类似 PageRank 在因果链上的变体），用于回答「这条知识凭什么可信」。
- **反事实查询**：如果删除源头 X，哪些对象会失效？返回受影响集合。
- 图索引异步构建：写入时记录边，用增量图合并；查询时 BFS + 剪枝。

### 3.3 签名与审计

- 每个溯源边可由写入者签名（Ed25519）。引擎验签，并只对已验证边计算可信度传导。
- 溯源图整体使用 Merkle DAG，支持「某时刻溯源链完整快照」的 O(log n) 证明（供审计方验证）。

## 4. 语义 GC 与记忆固化（Consolidation）

### 4.1 记忆层次

AINS 把记忆看作有层次的结构，而不是平铺对象：

| 层 | 内容 | 生成方式 |
|---|---|---|
| **Episode** | 原始事件、对话、日志 | 直接写入 |
| **Insight** | 从 Episode 提取的事实/偏好 | LLM 提取 + 溯源 |
| **Schema/Lesson** | 跨 Episode 的规律、策略 | Consolidation 摘要 |
| **Policy** | 需要稳定执行的决定 | 人工/高置信固化 |

`consolidate` 是一个后台意图：按调度扫描近期活跃子图，调用模型生成摘要；摘要本身是一个语义对象，其溯源指向被摘要的对象。原始对象可被降低权重（而非删除），保证可回溯。

### 4.2 语义 GC

- 冷且低引用、已被高置信摘要覆盖的 Episode，标记为可淘汰。
- 淘汰前生成 **墓碑对象（Tombstone）**：记住「这里曾有过什么、已被谁摘要替代」，避免溯源断链。
- 用户可显式要求「忘记」：触发删除 + 从摘要中移除对应信息（可追溯的删改记录）。

## 5. 注意力感知返回（Attention-Aware Serving）

### 5.1 认知块（Cognitive Chunk）

返回单位不是行，而是认知块：

```json
{
  "id": "chunk_7f3a",
  "text": "用户偏好在夜间使用暗色主题，最早见于 2026-10-20。",
  "tokens": 42,
  "confidence": 0.93,
  "evidence": ["obj_a", "obj_b"],
  "conflicts": [],
  "attention_score": 0.88,
  "freshness": "2026-10-30T10:00Z"
}
```

### 5.2 注意力密度

定义 **注意力密度**：

```
density = confidence × relevance / tokens
```

`pack` 算子选择使总 token ≤ 预算且总密度最大的子集（0/1 背包的贪心近似，按密度排序取）。

### 5.3 去重与互补

- 语义去重（LSH 近邻）避免重复。
- **互补选择**：如果两个块高度相似但各自包含部分信息，融合成摘要块（可选，通过轻量模型压缩）。
- 返回中标注「为什么选这块」，便于模型理解和使用。

## 6. 写时推理与反馈回路

### 6.1 推理性写入

有些写入不是原始事实，而是「由模型推导出的结论」。AINS 允许这些对象以 `inferred` 标记写入，并强制要求带溯源边，便于后续知识修订：

- 若上游对象被更新，所有依赖它的 `inferred` 对象会进入 **失效队列（Invalidation Queue）**，在下次读取时重新评估或降权。
- 这解决「知识漂移」问题：大模型从旧知识推导的结果不会永远有效。

### 6.2 反馈驱动的置信更新

- `adopted` 事件（用户/应用采纳）→ 置信度上升；`corrected` → 置信度下降并记录冲突。
- 置信度模型可以简单（Beta 分布）也可以学习。
- 置信度影响召回、合并与 GC 决策。

## 7. 安全与信任边界

- **信任分级**：来源可以是 `verified-human` / `trusted-agent` / `untrusted-agent`，意图约束可以要求最小信任级别。
- **提示注入防护**：召回文本可以带 `injected` 标记（由内容安全层判断），返回时隔离在单独字段，避免与可信内容混在一起。
- **权限在域级**，并可细化到标签，避免 Agent 通过语义推断越权。
