# 06 — 分布式设计

## 1. 拓扑

```text
                    ┌───────────────────────┐
                    │      Meta Plane        │
                    │ 域注册 / 拓扑 / 租约    │
                    └──────────┬────────────┘
                               │ gRPC 心跳 + 版本
   ┌───────────────────────────┼───────────────────────────┐
   ▼                           ▼                           ▼
┌───────────┐             ┌───────────┐             ┌───────────┐
│  Node A   │◄── 日志复制 ─►│  Node B   │◄── 日志复制 ─►│  Node C   │
│ ┌───────┐ │             │ ┌───────┐ │             │ ┌───────┐ │
│ │Shard 0│ │             │ │Shard 1│ │             │ │Shard 2│ │
│ │Shard 3│ │             │ │Shard 4│ │             │ │Shard 5│ │
│ └───────┘ │             │ └───────┘ │             │ └───────┘ │
└───────────┘             └───────────┘             └───────────┘
```

- **Meta Plane**：轻量共识服务（Raft），负责域注册、规则、拓扑、租约。不承载数据。
- **数据节点**：按 shard 组织存储；shard 由语义路由分配。
- **客户端**：SDK 缓存路由表，直接和对应节点通信。

## 2. 分片策略：语义路由

### 2.1 路由信号

数据域先按 **路由键** 决定 shard：

1. 显式 `routing_key`（如租户 ID）优先。
2. 否则，使用 embedding 的 **语义分区**：训练一个轻量 k-means / 量化码本，把语义空间切成 S 个区。
3. 否则，按 `id` 哈希（ULID 前缀哈希，保证时间局部性）。

### 2.2 为什么要语义分区

- **召回局部性**：语义相近的数据落在同一 shard，减少跨 shard 的向量检索。
- **缓存友好**：同一主题的查询命中同一节点缓存。
- **代价**：热点数据集中、重平衡成本高。用 **细粒度分片 + 虚拟分片** 缓解（一个 shard 包含多个虚拟分片，重平衡以虚拟分片为粒度）。

### 2.3 重平衡

- 目标：各节点虚拟分片数均衡、语义局部性尽量保留。
- 迁移以「虚拟分片 + 索引段」为单元，使用日志回放 + 段直传。
- 迁移期间双读（旧副本 + 新副本），迁移完成后切路由。

## 3. 复制模型

### 3.1 日志复制 = 主源

每个 shard 的语义日志约 3 副本：

- **Leader**：接受写，追加日志。
- **Follower**：异步/半同步复制日志，基于水位。
- 读取可从 follower 读，但必须声明它接受的最大陈旧度（`max_staleness`）。

### 3.2 因果令牌

- 每个写回执返回 `causal_token`：包含本 shard 的日志水位与已知上游令牌。
- 跨 shard 的写入（例如 A 写、B 读）通过令牌传递因果。
- 令牌可以随请求链（Agent 调用链）传播，保证因果先写的读取。

### 3.3 无主写入（可选）

对于 Eventual 一致的多模态大对象域，支持无主写入 + CRDT 合并（例如 last-writer-wins + 溯源记录），降低对 Leader 的依赖。

## 4. 一致性分层模型

| 模式 | 写路径 | 读路径 | 场景 |
|---|---|---|---|
| **Causal（默认）** | Leader + 半同步到 1 个副本 | 本地读 + 因果令牌合并 | Agent 记忆、RAG |
| **Strong** | Leader + quorum 持久化 | Leader 读或 quorum 读 | 策略 / 权限 / 配置 |
| **Eventual** | 任意节点写 | 本地读，后台合并 | 大对象、日志 |

**因果模式细节**：

- 写入返回时，至少一个 follower 已收到日志（可配置）。
- 读请求携带 `seen_epoch` 映射；节点返回时一并返回本地水位，客户端合并。
- 跨节点读写通过 **因果租约（Causal Lease）** 解决「写后立即跨节点读」：写完得到租约令牌，在租约有效期内读该域会强制路由到写过的 shard 或等待。

## 5. 分布式索引

- 本地索引在每次写入时更新；跨节点共享的索引（如全局溯源图、全局语义幂等）采用 **分片 + 聚合视图**。
- **语义指纹去重**：写入前先在本 shard 内部做 LSH 检测；跨 shard 用布隆过滤器广播（周期更新）避免全集群查询。
- 索引水位由 Meta Plane 管理，保证「索引构建完成后才对外可见」。

## 6. 故障与恢复

- 节点故障：Meta Plane 检测心跳，触发 Leader 选举。
- 网络分区：优先保证本地可用（Causal 模式下可继续读写，因果令牌会反映分区边界），并在分区恢复后合并冲突。
- 分区恢复协议：按 epoch 合并，产生 `ConflictSet`，再异步 `consolidate`。
- 数据损坏：段级 Merkle 校验；损坏段从副本恢复，若全部损坏则从上层日志备份恢复。

## 7. 多租户与资源隔离

- 每个租户的域有独立的 IO/内存配额。
- 租户隔离通过 shard 亲和 + 资源桶实现。
- 可配置「独占节点」：为特定租户固定节点，保证延迟。

## 8. 演进路线（单体 → 分布式的渐进增强）

1. **单机模式（v1）**：一个进程 + 本地 NVMe，接口与分布式一致，只是 Meta Plane 内嵌。
2. **主从复制（v2）**：增加日志复制、follower 读。
3. **分片（v3）**：按语义分区、路由表、重平衡。
4. **多区域（v4）**：区域间因果令牌、区域独立拓扑。

每一步都保持同一套 API 和语义等级，用户无需重写应用。
